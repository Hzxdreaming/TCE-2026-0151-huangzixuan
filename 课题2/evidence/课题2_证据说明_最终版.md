### 口径细则（24 行必须统一，不得中途换）

1. **认准页面顶部大字「当前温度」**，不取实时曲线右侧的「当前值」。
   二者同一时刻可差 1℃（预跑为 32℃ / 31℃），属刷新时刻与取整差异，
   **在备注里如实记下这个差异**，不要挑一个好看的抄。
2. 「健康状态 良好」是**分级文字**，只写进备注，不填 `电池温度_C`。
3. 同 App 的「CPU」标签页 `31℃` 是 **CPU 温度，不是电池温度**，
   可作辅助证据截图，但**不得混入电池温度列**。
4. 电池页「历史」图表需采集约 10 分钟后才显示 →
   每档跑满 30 分钟，**档末补截一张历史曲线**作为辅助证据。
5. ❌ 不作为数据来源：安兔兔**跑分**（会让 CPU/GPU 满载污染该档）、
   一键优化/清理加速/省电模式、任何网络评测文章里的温度/功耗/帧率数字。

## 三、口径声明（评审关注点，逐条守住）

| 字段 | 性质 | 规则 |
|------|------|------|
| `电量百分比` | 客观 | 安兔兔电池页整数百分比，现场即时读 |
| `电池温度_C` | 客观 | 安兔兔电池页顶部「当前温度」度数；**读不到则整列留空并声明** |
| `摄像头区_温感` `机身上部_温感` `机身下部_温感` `屏幕面_温感` | **主观** | 5 级序数：`0凉 / 1微温 / 2温 / 3热 / 4烫`。**非温度测量值，不是 ℃，不可反推度数** |
| `最热部位` | 文字 | 四点中等级最高者名称 |
| `环境温度_C` | 外部 | 空调面板 / 温湿度计 / 天气 App 的室温估计，备注写明来源，**不是手机测的** |
| 五分钟掉电、累计掉电 | 派生 | 由相邻行相减得出，**现场不算，回来录表时计算** |

温感判级固定动作：同一人、指背或手腕内侧、每点贴 2 秒、按
「机身上部 → 摄像头区 → 机身下部 → 屏幕面」固定顺序；**先摸四点再读电量与温度**，
避免手握机身额外加热。

**四区定位（本机）**：
- `摄像头区` = 背部**左上**徕卡四摄模组凸起处，四档摸同一位置
- `机身上部` = 背部中上（SoC 大致区域，避开摄像头模组）
- `机身下部` = 背部中下（电池区域）
- `屏幕面` = 正面**中央**，**不摸曲面边框**（本机为曲面屏）

**发热分布图只画 0~4 分级色块，不标 ℃；掉电/电池温度折线才标单位。**

## 五、异常与真实性（含本机限定，不写预设结论）

1. **整数百分比分辨率**：30 分钟内可能出现连续两个 5 分钟节点电量读数相同、
   `五分钟掉电 = 0`。属正常量化效应，**如实记录，不得为了让曲线好看改数**。
2. **温控降频**：麒麟 980 长时间高负载可能触发温度墙，游戏档后半段温度不再上升
   甚至回落、掉电变缓。属真实系统行为，**保留不剔除**，报告里归因「温控策略」。
3. **老机 + 旧系统限定**：本机 2019 年上市、电池已使用多年，安兔兔健康状态为「良好」
   （分级文字）；**安全补丁停留 2022年6月1日**，后台调度、温控策略与新机不同。
   因此**绝对掉电率不代表该机型新机水平**，本报告只做「同一台设备、四档工况横向对比」。
4. **起测电量超区间 / 档间落差（V5 新增，V9 定稿）**：P01 待机自 **97%** 起测
   （超出原定 60~90% 区间），P02 短视频自 **89%** 起测。P01 末行 96% 与 P02 基线 89%
   之间 **7 个百分点落在两档之间的非采样窗口**，两档又共用 11:20 这一时刻。
   **不猜测成因、不抹平、不拿任一值顶替另一档**；两档各自独立成立。
   跨档比较**只用掉电百分比与速率、不用绝对电量**，分析报告「局限说明」写明
   「各档起始电量不一致，档间存在未纳入采样的电量变化；本机为 2019 年设备、
   电池存在老化，故仅作同一设备四档工况的横向掉电率对比，不代表新机绝对水平」。
