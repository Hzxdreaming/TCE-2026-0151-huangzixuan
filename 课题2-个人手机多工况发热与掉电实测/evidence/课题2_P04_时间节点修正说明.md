## 二、这不是「改数」，但截图原值不抹

- 现场用另一台设备按 5 分钟节点计时，亮屏、进安兔兔、按截图有 1~2 分钟操作延迟，状态栏因此显示 14:12 / 14:26 —— 与 P02「计划 11:25、实读 11:26，备注晚 1 分钟」同类
- 用户作为记录人对**节点时刻**作确认/修正，数值（电量、温度）**一个没动**
- 为经得起评审交叉核对：台账与归档说明中**并列保留原始状态栏 14:12 / 14:26**，注明「按计时节点修正为 14:10 / 14:25」。⛔ 不假装截图变了，也不拿曲线反推数值

## 三、修正带来的三个影响

**① 起测时刻自然浮现**：按等距节点，第 0 分钟 = 15:55（墙钟）/ 13:55（状态栏）。15:54 那张游戏同框照正好落在起测前后约 1 分钟，**很可能转正为「起测时同框」**——但仍等用户报基线确认，不自行钉死。

**② 派生列可算了**：相邻五分钟掉电 `? / 2 / 3 / 1 / 2 / 2`（44→42→39→38→36→34）；首行待 47% 基线 + 起测时刻。掉电 `3→2→1→2` 的台阶如实保留，不插值、不平滑。

**③ 结论不变**：电池大字序列仍 `36/36/37/36/36/36` 全程水平，CPU 40~42℃ 平稳。P04 仍是四档里**最不热**的一档，P03 才是升温档。V30 那句「游戏档反而最不热、报告别写最热」继续有效。
